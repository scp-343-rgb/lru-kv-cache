## 2. 三分钟 KV 项目介绍

目标时长：2.5–3 分钟。

### 2.1 项目目标

- 项目解决什么问题：在容量受限的 KV 缓存中，既要通过 key 快速定位数据，又要在容量满时淘汰最久未使用的数据；同时支持进程重启后恢复缓存快照。
- 最小可运行版本包含什么：可编译运行的 CLI，支持 `put`、`get`、LRU 容量淘汰和 `dumpFile` / `loadFile`；在此基础上再加入全局 `mutex` 和 benchmark。

填写关键词：

### 2.2 核心数据结构与 get/put

必须能讲清：

- `unordered_map` 存什么：存取key到链表指针的映射，通过key来对应链表结点
- 双向链表维护什么：维护最近使用顺序
- 为什么两者结合能做到平均 O(1) 查询与淘汰：哈希表O(1)的查找结点指针，链表拿到指针后可实现O(1)的查找，插入和删除
- `get` 命中时发生什么：找到对应结点，返回value，并执行moveToHead；未命中会返回false，不修改链表
- `put` 遇到已有 key 时发生什么：更新当前key的value值，然后把结点移到链表头
- `put` 遇到容量满时发生什么：删除尾结点，在unordered_map里删除对应的key，释放结点，再插入新节点
- 头节点和尾节点分别代表什么：头节点是最近使用的结点，尾结点是最久未使用过的结点

### 2.3 持久化

必须能讲清：

- `dumpFile` 写什么：将当前数据写入磁盘
- 文件记录格式：记录格式采用utf-8格式，一行对应一条缓存记录，每一行包含key和value两个字段，并用一个制表符分隔
- 为什么要按 MRU → LRU 写入：因为写入顺序是从上到下，保证最近使用结点在第一行
- `loadFile` 为什么倒序重新 `put`：因为链表采用头插法记录数据，倒序才能保证头节点是最近访问节点
- 非法行如何处理：如果是空行默认跳过；制表符缺少或过多，key和value为空向stderr输出行号并报错，然后跳过该行，继续读取后续数据
- 当前持久化的局限：key和value不支持TAB和换行，重复key没有特殊处理情况

### 2.4 并发保护

必须能讲清：

- 为什么加锁：共享资源同一时间只允许一个线程进行访问
- 锁保护了哪些操作：get，put，dumpfile，loadfile
- `get` 为什么也需要加锁：多个线程同时修改哈希表和链表指针，会导致数据竞争，状态不一致

### 2.6 主动说明局限

- 当前使用全局 mutex：`get` / `put` / `save` / `load` 共用一把锁，不同 key 也会串行；后续可考虑按哈希分桶的分段锁。
- 持久化不是原子快照：写入中途崩溃可能留下不完整文件；当前没有临时文件替换或恢复校验。
- benchmark 使用均匀随机访问：没有热点和访问局部性，三策略命中率差异很小，不能据此判断真实业务中的策略优劣。
- 已完成 FIFO / 随机淘汰对比：固定 seed、相同 workload 和统计口径；但当前 workload 下 LRU 不一定占优，不能把局部结果外推。

## 5. 高频项目追问清单

回答时只写关键词或事实来源，不写长篇答案。

### LRU

- [ ] 为什么 `unordered_map` 需要存 `Node*`，而不是只存 value？因为要通过key来找到对应的链表结点
- [ ] `get` 和 `put` 的时间复杂度是多少？都是O(1)
- [ ] 容量为 1、重复 `put`、连续 `get` 时分别如何处理？重复put会不断更新key对应的元素，如果是不同数据，会不断更新；连续get链表中的结点不变，因为只有一个数据
- [ ] 为什么不用单链表？通过哈希表拿到结点指针后，双向链表由于可以直接找到前驱后继，可以直接完成移动删除操作
- [ ] 哈希表冲突是否影响链表顺序？不影响，哈希冲突只是影响查找的时间复杂度

### 持久化

- [ ] 为什么 `dumpFile` 不会改变链表顺序？因为它通过遍历链表来获取信息，没有调用对应的get/put操作
- [ ] `loadFile` 为什么倒序 `put`？因为头插法得到的顺序是倒序
- [ ] 加载到一半遇到非法行怎么办？向stderr报错输出行号，继续读取后面数据
- [ ] 进程在写入过程中崩溃会怎样？丢失数据
- [ ] 当前格式有哪些字段限制？value/key不能为空，只能有且只有一个制表符

### 并发

- [ ] 为什么 `get` 也要加锁？因为get命中会执行moveToHead，修改链表顺序，同时get导致数据竞争
- [ ] 全局锁会不会让并发退化成串行？会
- [ ] 四线程压测的每次操作具体是什么？五次操作中执行一次put四次get
- [ ] QPS 如何计算？通过总操作数除以整个过程耗时
- [ ] 下一步如何降低锁竞争？进行哈希分桶，通过分桶实现分段锁

### Benchmark

- [ ] 为什么固定 seed 才能比较不同容量？这样才能保证每次引擎生成的数据相同
- [ ] 为什么命中率只统计 `get`，不统计 `put`？get是查询语义，put是写入和更新，不属于一次缓存查询
- [ ] 为什么当前命中率不能直接代表真实线上表现？依赖容量大小，key的空间大小，put比例，访问序列等
- [ ] 如果要比较 LRU、FIFO、随机淘汰，哪些变量必须保持一致？workload，key空间大小，访问序列，seed，put比例
