# 持久化格式 v1

## 1. 文件与记录格式

- 文件采用 UTF-8 文本格式，一行对应一条缓存记录。
- 每条记录恰好包含两个字段：`key` 和 `value`。
- 两个字段之间必须使用一个 ASCII 制表符（TAB，字节值 `0x09`）分隔。
- 本文档中的 `<TAB>` 只用于表示一个制表符，不是五个普通字符。
- 合法记录格式：

```text
key<TAB>value
```

例如，以下内容中 `<TAB>` 都应替换成实际的制表符：

```text
name<TAB>Alice
city<TAB>Beijing
```

- 文件为空是合法的，表示缓存中没有记录。
- LF 和 CRLF 均可作为换行符。

## 2. 字段规则

- `key` 和 `value` 都不能为空。
- 每一行只能有一个制表符，因此字段数量必须恰好为两个。
- 正常 CLI 输入不会产生包含空格的 key/value；v1 中该限制由调用方保证。
- v1 暂不专门校验 key/value 内部的空白字符。
- v1 暂不专门处理外部文件中的重复 key；`dumpFile` 从缓存导出的记录本身不会产生重复 key。

## 3. 写入顺序

- `dumpFile` 从链表头到尾写入：先写最近使用（MRU），最后写最久未使用（LRU）。
- 目标文件已存在时覆盖旧内容，每次生成当前缓存的完整快照。
- `loadFile` 加载完成后，有效记录的相对顺序必须与写入时一致。

## 4. v1 非法行处理

加载只做以下四类结构校验。非法行会被跳过，后续行继续读取，不因单行损坏使整个文件加载失败。

- 空行：静默跳过。
- 缺少 TAB：跳过，并向 `stderr` 输出行号和原因。
- TAB 多于一个：跳过，并向 `stderr` 输出行号和原因。
- key 或 value 为空：跳过，并向 `stderr` 输出行号和原因。

## 5. 加载结果

- 文件不存在或无法打开时，加载操作返回失败，调用者向 `stderr` 输出错误信息。
- 没有记录或所有记录均非法时，加载成功，缓存保持为空。
- 单个非法行不影响其他合法行。
- 加载结束后，有效记录按第 3 节规定的顺序恢复。

## 6. 后续可选改进

以下内容不纳入当前 W4，只记录为后续可选升级项：

- 严格校验 key/value 中的空格、制表符和其他空白字符，并输出具体行号。
- 定义并实现外部文件中重复 key 的处理策略，例如保留第一条或最后一条。
- 支持转义字符，使 key/value 可以包含空格、TAB 或换行。
- 输出加载统计，例如成功记录数、跳过行数和失败原因汇总。
