# Benchmark

## 环境

- 平台：Windows + MSYS2 UCRT64
- 编译器：g++ 15.2
- 标准：C++17
- 优化：`-O2`

## 实验配置

| 参数 | 值 |
| --- | ---: |
| 随机种子 | 20261116 |
| 操作总数 | 100000 |
| key 空间 | 10000 |
| put 比例 | 20% |
| 淘汰策略 | LRU |
| 容量 | 10 / 100 / 1000 / 10000 |

## LRU 容量扫描结果

```text
capacity=10    gets=80064 hits=92    misses=79972 hit_rate=0.00114908
capacity=100   gets=80064 hits=820   misses=79244 hit_rate=0.0102418
capacity=1000  gets=80064 hits=7806  misses=72258 hit_rate=0.097497
capacity=10000 gets=80064 hits=45350 misses=34714 hit_rate=0.566422
```

| 容量 | gets | hits | misses | hit_rate | 百分比 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 10 | 80064 | 92 | 79972 | 0.00114908 | 0.114908% |
| 100 | 80064 | 820 | 79244 | 0.0102418 | 1.02418% |
| 1000 | 80064 | 7806 | 72258 | 0.097497 | 9.7497% |
| 10000 | 80064 | 45350 | 34714 | 0.566422 | 56.6422% |

说明：`hit_rate = hits / gets`，put 不计入 hit/miss。两轮运行结果完全一致，且每轮均满足 `hits + misses == gets == 80064`。

## 观察与限制

- 容量从 10 增加到 10000 时，命中率单调上升。
- 当前 workload 为均匀随机访问，容量很大时能保存更多 key，因此命中率明显提高。
- 该结果暂不用于比较 LRU、FIFO 和随机淘汰的优劣；三者对比需要复用同一份 workload，并加入能体现访问局部性的请求模式。
